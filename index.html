GastroLite AI: A Resource-Aware Approach to Gastric Histopathological Image Classification

Exploring whether lightweight deep learning models can provide an effective balance between classification performance and the computational requirements of deployment.

By Mahvish Ishaq · M.Tech CSE
Gastric histopathology · Lightweight CNNs · Resource-aware evaluation · Web deployment

Introduction

Gastric cancer is a major health concern, and histopathological examination plays an important role in studying tissue abnormalities. Deep learning has become useful for image-based classification, but high-performing models can also introduce greater computational and storage requirements.

This motivated the development of GastroLite AI, a deployment-oriented research framework that investigates lightweight convolutional neural network architectures for gastric histopathological image classification. Rather than considering accuracy alone, the project evaluates the models from both performance and resource perspectives.

The objective is not to create a clinical diagnostic system. Instead, the work investigates a practical research question: how can a compact deep learning model provide strong classification performance while remaining comparatively efficient for deployment?

Why a Lightweight Model?

In an image-classification system, accuracy is only one part of the picture. The number of model parameters, storage size, floating-point operations, inference latency, and training requirements can affect how easily a model can be deployed.

“The goal of GastroLite AI is not simply to find the most accurate model, but to identify a practical balance between predictive performance and resource requirements.”

This resource-aware perspective is particularly relevant when a model is intended to move beyond experimentation and into a usable software prototype.

Dataset & Preprocessing

The project uses the GasHisSDB histopathological image dataset. The images are used for binary classification into Normal and Abnormal categories.

Images are resized to 224 × 224 pixels and normalized using the standard ImageNet mean and standard deviation. Training augmentation includes horizontal flipping and rotation of up to 10 degrees. The same overall preprocessing approach is used for the model comparison.

Methodology

The experimental workflow begins with dataset preparation and preprocessing, followed by model training and validation. Four lightweight CNN architectures are then evaluated using the defined experimental setup.

Four architectures were compared

MobileNetV2, MobileNetV3-Small, EfficientNet-B0, and ShuffleNetV2 were selected for comparison because they represent compact CNN architectures suitable for resource-conscious experimentation.

The reported comparison uses five training epochs and a batch size of 32. After classification performance was evaluated, resource measurements were considered to identify the model offering the most suitable overall trade-off for the prototype.

Key finding Although EfficientNet-B0 achieved the highest reported test accuracy, MobileNetV3-Small offered a strong resource-performance balance, with a compact 5.93 MB model, 61.46M FLOPs, and the lowest reported per-image inference time among the four models. It was therefore selected for the deployment prototype.

Resource-Aware Model Selection

The project does not treat model selection as an accuracy-only problem. Performance and cost-related measurements are normalized so that the different metrics can be considered together. Cost-oriented metrics are inverted during normalization, allowing lower resource usage to contribute positively to the overall resource-aware score.

This approach makes the comparison more deployment-oriented: a model that is slightly more accurate but substantially larger or more computationally demanding does not automatically become the preferred model.

Based on the project's reported resource-aware assessment, MobileNetV3-Small was selected as the model used in the web demonstration.

From Experiment to Web Prototype

After model evaluation, the selected model was integrated into a web-based prototype. The purpose of the interface is to demonstrate the complete flow from image upload to model inference and presentation of the predicted category.

The prototype allows a user to upload a gastric histopathological image, process it using the trained MobileNetV3-Small model, and view the resulting Normal or Abnormal classification together with the displayed confidence value.

What the Results Mean

The experiments show that lightweight architectures can achieve high classification accuracy on the selected dataset while differing substantially in their computational requirements. This highlights why deployment-oriented evaluation should consider more than a single predictive metric.

MobileNetV3-Small was chosen for the prototype because its resource profile makes it attractive for a lightweight implementation. The selection should be understood within the scope of this experiment; it does not imply that the model is clinically superior to the other architectures.

Important: GastroLite AI is a research and educational prototype. Its predictions are not medical diagnoses and should not be used to make clinical decisions or replace evaluation by qualified healthcare professionals.

Limitations & Future Work

The current work is based on a public dataset and a defined experimental setup. Further studies would be needed to determine how the selected model behaves on independent datasets and images acquired under different conditions.

Future work could include external validation, broader dataset testing, explainability studies, model calibration, usability evaluation, and assessment with clinical experts. These steps would be important before considering any real-world clinical application.

Conclusion

GastroLite AI presents a resource-aware approach to gastric histopathological image classification by evaluating lightweight deep learning architectures from both performance and computational perspectives. Four models were compared, and MobileNetV3-Small was selected for the deployment prototype based on the project's reported overall trade-off.

The project demonstrates that model selection for deployment can be approached as a balance between what a model can predict and what it costs to run. The accompanying web prototype provides a simple demonstration of that selected model in an end-to-end workflow.
